# Changelog

All notable changes to OpenSignup are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow semantic versioning.

## [Unreleased]

### Added
- Activity events for the steps where new organizers stop (#500), so they can be counted: `signup.link_copied` when an organizer copies a signup's link from its header (sent from the browser to `POST /api/signups/[id]/link-events`, which takes only a signed-in member of the signup's workspace, 60 an hour each), `magic_compose.failed` with the AI draft's error code, `refusal`, `not_saved` or `over_limit`, and `signup.publish_refused` when a publish is turned down for having no slots or because the signup was closed or archived meanwhile, from the browser, the API or a connected assistant. A publish of a signup that's already open isn't counted as refused. The publish refusal for a signup with no slots now names `field: 'slots'`. The organizer's page views (`signup.draft_started`, `signup.viewed` on the Build tab, `signup.editor_opened`, `signup.previewed`) now say whether they were opened on a phone or a computer (`device`), and `signup.draft_started` says which form the page showed (`mode: 'magic' | 'manual'`). Payloads hold codes and kinds only: no prompt, no email, no User-Agent. `docs/telemetry.md` lists them, and the privacy page says the log records these.
- Participants are emailed when the organizer moves their slot to a new date or time (#524). The email ("Time changed: <signup> · <slot>") prints the slot's new details and the participant's link to change or cancel, and goes about 10 minutes after the organizer's last change, so a date and then a time, or a date typed day by day, send one email for where the slot ended up, and a slot moved back before then sends none. It follows the reminders setting: with reminders off, or for someone who unsubscribed, nothing is sent, and the unsubscribe link and page now say they stop these emails too. A reminder for a time the participant was already told about reads as a normal "Reminder"; "Time changed" now means their last email, whatever it was, was for another time. Moves are made through the Build tab, a group heading or the `update_slot` tool; a field change that re-times every slot (a deleted time field, a new reminder date) sends nothing. In the Build tab, a slot's editor now says how many people are signed up for it and whether they'll be told if it moves. Each move writes a `slot.rescheduled` activity row (`{ slotId, from, to }`) and each email a `slot.change_sent` row. The worker gains two queues, `slot-changes.dispatch` (every 2 minutes) and `slot-changes.send`; it creates them itself when it starts, so there is nothing to migrate.
- `pnpm eval:mcp`, an opt-in eval of what a connected AI assistant builds through the MCP tools (#254). It sends each case in `evals/magic-compose/dev-evals.json` to a tool-calling model with the server instructions and the tool list, takes the arguments of its `create_signup` call, and scores them with the checks the Magic Compose evals use, now shared in `scripts/lib/eval-harness.ts`. It reuses the `LLM_*` settings and needs no database. Like `pnpm eval:magic-compose`, it is run by hand, never in CI. Two new cases check that a signup for parents at each game gets one dated slot per game, with the right capacity, and no fields for names, emails or what someone brings.
- Follow-up cases for `pnpm eval:mcp` (#477), in `evals/mcp/followup-evals.json`: the organizer says more after the assistant has made the signup, as in "add an earlier slot for setup", "each dish needs to feed 20 people, about 200 people in total" and "show me what you made". A case lists those messages in `followUps`. Every tool call in these cases is answered by the real MCP tools against the local Postgres (`DATABASE_URL`, as for `pnpm test:db`), with a new organizer and workspace for each case, and the case is scored on the tools called after the first message, the signup's slots before and after, and the last reply (a Markdown table with a row per slot, and `links.edit`). The single-message cases run as before and still need no database. `pnpm eval:mcp --tag=follow_up` runs only the new ones.
- An instance can add its own links to the site footer, shown before Help, by listing them in `src/lib/footer-links.ts`. The list is empty here, so the footer is unchanged; a deployment that serves pages of its own fills in its own copy, and every page links to them without that deployment editing the footer.
- Organizers can take one person off a slot (#377). Each active row on the Responses tab has a **Remove** button, named for screen readers by the person and slot ("Remove Sam Example from Fruit and water"), which asks first ("Remove Sam Example from Fruit and water? Their spot opens up for someone else. They won't get an email about it.") and then cancels that one sign-up, so its spots open up again. The question opens in a dialog over the table, so the table doesn't move and nothing behind it can be used until it closes; Escape or **Keep** closes it and returns to Remove. On a screen narrower than 768px, where the table didn't fit, each person is a card instead: name and status, then the slot, then the email and Remove, with nothing to scroll sideways. Status is a coloured label everywhere, green for confirmed and grey for cancelled, removed or moved, so a row without Remove says why. On a phone, Remove, **Keep** and **Yes, remove** are 44px tall, and the dialog fits the screen. Until now the only way was to delete the whole slot, taking everyone on it. The person gets no email; their edit link says "The organizer took you off this slot" and names the slot, also when they had moved there from another slot, and the public page no longer shows them as signed up. Their row stays on the Responses tab with the Status "removed"; the old row of a move to another slot now says "moved" rather than "cancelled", and the tab's count leaves out every cancelled sign-up (the CSV export keeps the stored status). Owners, admins and editors can remove someone; a viewer is told "You don’t have edit access.", and someone whose slot or signup was deleted meanwhile gets "This person is no longer on this signup. Reload to see the latest." Removing someone already cancelled changes nothing. A new help page, "Take someone off a slot", walks through it. Each removal writes a `commitment.removed` activity row (`{ commitmentId, participantId, slotId }`) by the organizer, in the same transaction as the cancel; `event_type` is plain text, so no migration is needed.
- Landing-page CTA click telemetry (`landing.cta_clicked` activity event).
- Initial v1 scaffolding: Next.js 15 + TypeScript + Drizzle + Auth.js v5 + pg-boss.
- Full entity schema (workspaces, organizers, members, signups, slot groups, slots, participants, commitments, activity, magic links, claims).
- Zod schemas as source of truth with discriminated union on `slot_type`.
- Capacity-safe commitment service with `(slot_id, position)` unique enforcement.
- Organizer magic-link login and personal-workspace auto-create.
- Mobile-first participant page with bottom-drawer commit flow.
- Reminder emails the day before a dated slot, via pg-boss.
- Pluggable email transport: console, SMTP, Resend.
- AGPL-3.0 license.
- Organizers can let participants sign up without an email (#378). The signup's `requireEmail` setting, on by default, is set on the Settings tab, in a new "Sign-up form" section: "Ask for an email address", Required or Optional, then Save. The AI connector's `update_signup` tool and `PATCH /api/signups/[id]` can set it too. A line under the choices says what the one picked means, and changes as soon as the radio does: with Required, everyone is emailed their link to change or cancel; with Optional, people who leave it blank get no emails, not even reminders, so they need to save their link, and someone who loses it can sign up again while the organizer removes the old one on the Responses tab. A viewer is refused with "You don’t have edit access.", the words the Build tab now uses too in place of "You no longer have edit access.", and a refused Delete on the same tab is put in the same plain words instead of the service's own message. With it off, the sign-up form's Email box says "(optional)" and starts blank, even for someone this browser remembers. Its help says what an email brings (the link, and a reminder only where that slot will get one) and to save the link without one. Someone who leaves it blank gets no confirmation or reminder emails. Their link to change or cancel is not emailed: the confirmation screen shows it, says to save it and offers Copy link in place of Share link, which on a phone invited them to post it, and the `os_commit` cookie keeps it in that browser. If the organizer turns it back on after the page loaded, the refused blank email turns the box required. In `POST /api/slots/[id]/commitments`, a blank, whitespace-only, null or missing `email` now means none: a signup that requires one refuses it with `invalid_input` on `email`, and one that doesn't always adds a new participant, as there is nothing to find them by. Turning the setting back on asks only new sign-ups: anyone already signed up without an email keeps their spot and can still change or move it. `get_signup` and the other connector tools now show `requireEmail`; `update_signup` advertises no default for any setting, so a client that fills in defaults cannot turn it back on with an unrelated change. The privacy and cookies pages and the help pages say what happens without an email, and the help page "Create and publish your first signup" explains the setting and what to do when someone loses their link. The "Sorry, this link isn’t working" page tells everyone to contact the organizer, and to try their confirmation email's link only if they got one.

### Changed
- **Duplicate** on the Build tab now puts the copy straight after the slot it copies, and opens it (#557). The copy used to go to the end of the list (or of its group), often off screen, while the editor stayed on the original, so the date people changed next moved the original instead of the copy. Now the original's editor closes, the copy's opens right below it with focus in its first field, and the order holds after a reload. Duplicate in a closed row's toolbar does the same. The copy is added through `POST /api/signups/[id]/slots/bulk` with `beforeSlotId`. The help page "Create and publish your first signup" says where the copy goes.
- Magic Compose is now told to make one slot with a capacity when several people can take the same thing, rather than a row per person (#501). The AI connector's server instructions already had the rule ("5 shifts that need 8 people each is 5 slots with capacity 8, not 40 identical rows"); the Magic Compose prompt now has it too, in its own short section after the cross-product rule, and it is one of the rules a test on each side checks word for word. The server instructions are unchanged. The "Classroom or school" starter prompt now says "20 families are each bringing one dish: we need 5 families on mains, 5 on sides, 5 on desserts and 5 on drinks." in place of "20 families. We need mains, sides, desserts, and drinks, roughly 5 of each", which read as a row per family. A new eval case runs that starter word for word and expects one slot per dish type with capacity 5, and the existing capacity cases are tagged `capacity_not_duplicate_rows` so one run covers them all.
- The builder's slot editor calls the number of places on a slot **Spots**, the word the signup page and help already use, instead of **Capacity** (#140). A line under it says "How many places people can take. Leave blank for no limit.", and screen readers hear it too; a blank box reads "No limit" instead of ∞. A closed slot row counts "2 of 15 taken", or "4 taken" when there is no limit, instead of "2/15" and "4/∞". Only the wording changes: the API and the MCP tools still call it `capacity`.
- The responses download moved from the signup header to the Responses tab, as **Download CSV** (#559). It sits above the table, beside a summary line such as "5 sign-ups · 1 cancelled · 1 removed": sign-ups is the tab's count of active ones, and parts that would read 0 are left out, as is the old half of a move. On a phone the summary and the button are on rows of their own, and the button is 44px tall. With no sign-ups there's neither, only the empty-state box. The header's **Export** button and the phone menu's **Export responses** are gone, as is the line "Export to CSV from the header.", and on a phone a closed or archived signup no longer shows a ⋯ menu that would open empty. The file and its address, `/api/signups/[id]/export.csv`, are unchanged.
- `PATCH` and `DELETE /api/signups/[id]/fields/[fieldId]` now check that the field belongs to the signup the URL names (#554). A field of another signup answers 404 `not_found`, as a field that doesn't exist does, instead of being changed through the wrong signup's URL. The builder always pairs a field with its own signup, so no screen changes, and the MCP field tools, which name the field alone, are unchanged.
- Error and success messages on the Magic Compose page, the sign-up dialog, the page for changing your spot, Connected apps and the sign-in page now use the same red or green box as the rest of the app (#523). They had copied it by hand and drifted: the AI draft error and the sign-up dialog's refusal had more padding, and the sign-in page's "That sign-in link is no longer valid…" was plain red text with no box. Each message keeps its words, and screen readers still hear refusals as alerts and successes as status updates.
- A signup's visibility can no longer be changed, because nothing reads it (#517): every signup opens for anyone with its link, and none is listed or indexed. `PATCH /api/signups/[id]` now refuses `visibility` with `invalid_input` instead of saving `public`, `unlisted` or `password` (no password existed) and returning 200. The MCP `update_signup` tool no longer offers it, and `list_signups`, `get_signup` and the other tools no longer report it. New signups are still stored as `unlisted`, and the column stays. A script that sends `visibility` in a PATCH needs to stop.
- The Slot column on the Responses tab shows a slot's values without their labels: "Set up tables · Sat, Nov 14" instead of "Job: Set up tables · Date: Sat, Nov 14" (#411). The column heading already says Slot, the cells are about half as long, and the slot reads the same way as in the Remove question on the same tab. Emails and the responses download are unchanged.
- The responses download (**Export**) now has one column per signup field, headed by the field's label and in field order, so a spreadsheet can sort or filter it by day or item (#474). It used to put every field in one JSON cell, `slot_values`. Dates are written as `YYYY-MM-DD`, times as `HH:MM` and numbers as numbers, as they're stored, not as the page shows them. After the fields come Name, Email, Status, Spots, Notes and Signed up. Status now says "removed" or "moved" where the Responses tab does, instead of "cancelled" for everyone. The `slot_ref` and `slot_at` columns are gone: one is an internal key, the other the reminder job's noon-UTC stand-in for a slot with only a date. Two fields with the same label, or a field named like one of the fixed columns, get headers like "Time (2)". The file is now `<slug>-responses.csv`, and starts with a UTF-8 byte-order mark so Excel on Windows reads accented names correctly. Before upgrading: anything that reads this file by its old column names (`participant_email`, `slot_values` and the rest) or its old file name needs changing.
- The app now spells "signup" one way and calls what one person holds their "spot" (#456), as the help pages' style guide already asked. The builder's empty title reads "Untitled signup", and screen readers hear "Signup title" and "Signup description". A save refused because the signup closed says "This signup is closed." The page for changing or cancelling a spot is headed "Your spot", its closed banner is titled "Closed" like the public page's, and the **Edit** button on the public page is named "Edit your spot for …". The sign-up dialog's closed error says "No one new can sign up for this slot now.", the edit page's says "You can't add more spots now.", and the broken-link page, the cancel error, the reminder email and the privacy page say "your spot" where they said "your sign-up". The `update_signup` tool description says turning `requireEmail` back on "applies only to people who sign up after that". "Sign-up" with a hyphen stays only before a noun: "sign-up sheets", "sign-up coordination" and the **Sign-up form** heading. `docs/writing-help.md` now states that rule for screens, emails and tool descriptions too.
- A connected AI assistant now places a field the way it places a slot (#424). `add_field` takes `beforeFieldId` in place of `sortOrder`: the new field goes in front of that field, and the fields after it move along one. A new `reorder_fields` tool takes every field id of the signup once, in the new order, numbers them 0..n-1, and moves each slot's reminder time when the new order pairs a different time field with the date. `update_field` no longer takes `sortOrder`. `add_field` and `update_field` now refuse a `sortOrder` with `invalid_input` and name what to use instead. A number set on one field could tie with another field: a field put at 0 landed second, and fields that `create_signup` made together could come back in either order from one read to the next. That order is the order of the columns on the signup page and of the lines in participants' emails. Fields that share a position are now listed in a fixed order everywhere. The Build tab and the REST API still take `sortOrder`.
- A viewer who chooses Publish, Close signup or Delete now gets a message saying “You don’t have edit access.” instead of the error page (#390). Publish and Close signup used to say nothing at all when they were refused; now the reason shows on a computer in a full-width line under the signup’s header, above the tabs, and on a phone under the button in the More actions sheet: “Add a slot before publishing.” for a signup with no slots, “This signup changed since the page loaded. Reload to see the latest.” when another tab already published or closed it, and “This signup is no longer available.” once it’s deleted. Delete’s refusal shows on the Settings tab, as its other refusals already did. The signup page’s server actions now share one helper, `refusalAsResult` in `src/lib/errors.ts`, that turns a refusal thrown by a policy guard into the same `Result` error the service returns for every other refusal.
- Sign-in no longer writes email addresses to the server logs (#450). The "magic link dispatched" line, the two lines for a send that outlived its time limit, and the "magic link rate-limited" warning now give the address's domain (`emailDomain`) instead of the address, and the rate-limit warning no longer gives the IP; its bucket says which limit was hit. The hourly housekeeping job now also deletes expired sign-in tokens (`verification_tokens`). Auth.js only deleted one when its link was used, so every unclicked link, including links anyone can ask for on someone else's address, kept that address in the table for good; the first run after upgrading clears the backlog. Housekeeping's log line and return value gain a `verificationTokens` count. The privacy page now says logs leave out email addresses and that the hourly cleanup covers sign-in tokens as well as codes. Expired `sessions` rows are still not swept: they hold an organizer id, not an address, and are left for their own change.
- `GET /api/public/signups/[slug]` now sends an allow-list of what a participant needs, the same things the public page shows (#452): the signup's `slug`, `title`, `description`, `status`, `opensAt` and `closesAt`; from its settings only `requireEmail`, `sendReminders` and `groupByFieldRefs`; each field's `ref`, `label`, `fieldType` and `config`; each slot as the page renders it (`id`, `ref`, `values`, `slotAt`, `hasTime`, `capacity`, `status`, `committed`); and `committedBySlot`. It used to send the whole database row, so a server-only column added later would have gone public without anyone deciding it should. No longer sent: the signup's `id`, `workspaceId`, `organizerId`, `visibility`, `theme`, `tags`, `claimTokenHash`, `deletedAt`, `createdAt`, `updatedAt` and its other settings (`lockoutHoursBeforeSlot`, `reminderFromFieldRef`, `confirmationMessage` and the rest); each field's `id` and `sortOrder` (fields still come in order); each slot's `workspaceId`, `signupId`, `priceCents`, `sortOrder`, `createdAt` and `updatedAt`. The app doesn't call this endpoint, but a script that reads any of the dropped keys needs updating.
- After "Yes, cancel" on the page for changing or cancelling a sign-up, that page now says "Your spot was cancelled", names the slot and links back to the signup (#458). It used to go straight back to the sign-up sheet with no word that the cancel worked, and if the browser held another sign-up on the same sheet, its "You're signed up" bar could read as though the cancel had failed. The page is the one the link already showed when opened again after a cancel.
- The workspace policy guards now refuse a signup, slot or other row with no workspace to everyone, organizers included (#453). They used to let any caller through for such a row, anonymous visitors too, on the strength of ownership checks that didn't exist. Nothing creates a row without a workspace, so nothing changes today; the guards just no longer fail open.
- A reminder unsubscribe link that is incomplete or no longer valid now shows the same centred card as the other participant pages (a signup that isn't open yet, a cancelled sign-up), instead of a card of its own (#370). The words are unchanged.
- A connected AI assistant is now told who fills in a signup's fields (#475). The `create_signup` and `add_field` descriptions say fields are columns the organizer fills in to describe each slot, that participants don't fill them in, and that everyone who signs up already gives a name, can leave a note and gives an email unless the signup makes it optional. The server instructions add one line under "Designing a signup" saying not to add fields for those. Assistants were adding "Parent name" or "Snack" fields that nobody could fill in. The Magic Compose prompt is unchanged.
- The AI connector's `create_signup` tool now refuses a call where a field has no value in any slot, with `invalid_input` naming each such field, and creates nothing (#476). Assistants added columns like "Parent name" thinking people who sign up would fill them in, and got a signup with a column nobody could fill. The message says fields are columns the organizer fills in and that people who sign up give their own name, email and note. A field with a value in at least one slot is still accepted, and a field whose values were all in the wrong format is reported once, as a format problem. Magic Compose, `add_field`, `add_slots` and `update_slot` are unchanged.
- Magic Compose's sparkle, check and arrow icons now come from the icon set the rest of the app uses, so the sparkle is outlined rather than filled (#368). A day's header in the builder now reads to screen readers as "Thu, May 21" rather than "THU, MAY 21"; it still shows in capitals. When drafting times out, the message now says only "AI drafting timed out. Try a simpler prompt.": it no longer tells the organizer to raise `LLM_TIMEOUT_MS`, a setting only whoever runs the site can change, and the server log still names the limit that ran out.
- The help pages now give search results and link previews a description of 110 to 160 characters, as the rest of the site does (#392). `/help` used to say only "Short guides to making signups on …", and each article reused its one-line summary from the list on `/help`, which was too short for site audits and more likely to be swapped for a snippet of the search engine's own. Each article in `src/help/articles.ts` now has a `description` beside its `summary`, and a test holds every one, `/help`'s included, to that length. The list on `/help` is unchanged.
- On a closed signup, someone who signed up now still sees the "You're signed up" bar with its **Edit or cancel** link (or **Manage**, for more than one slot), under the Closed banner (#400). The Closed banner used to replace it, so a returning participant lost the quickest way to change or cancel, and could read "This signup is no longer collecting responses." as their spot being gone. Closing only stops new sign-ups, so for them the banner now says "No one new can sign up, but your spot is still yours." ("your spots are still yours" for more than one slot). Visitors who haven't signed up, the organizer's preview and archived signups see what they did before.
- The page for changing or cancelling a sign-up now names its slot under the "Your signup" heading, in the same words as the cancelled page and the confirmation email's subject, e.g. "Run the till · Sat, Nov 14" (#409). Someone with more than one sign-up, or none of the emails to check, couldn't tell which one they were about to change. A slot with no values to show gets no line.
- Dragging a slot to a new place in the builder now saves the whole order in one request, `PUT /api/signups/[id]/slots/order` with `{ slotIds }`, which puts every slot in place in one transaction or changes none (#326). It used to send one request per slot that moved, so a failure part-way, or another tab or an AI assistant changing the slots between them, could leave some slots in their new places and some in their old, with ties. The list has to name every slot of the signup once, as the connector's `reorder_slots` tool already required. If a slot was added or removed elsewhere since the page loaded, the save is refused, and the builder reloads the slots so the organizer can drag again, with the message "The slots changed in another window, so your move wasn't saved. Drag it again." A normal drag looks the same as before.
- After signing up without an email, pressing Copy link now says "Link copied" on the button itself for a moment, as Share link does, instead of on a line under the buttons, where it sat beneath Add to calendar and read as that button's result (#408). Screen readers still hear "Link copied.", and if the browser won't copy, the line saying to copy the link by hand still shows.
- The page for changing or cancelling a sign-up now labels its boxes "Your name" and "Notes (optional)", as the sign-up sheet does, where it used to say "Name" and "Notes" (#410). Notes was optional on both, but only the sheet said so.
- The link to change or cancel, shown after signing up, now wraps only after `/`, `-`, `?`, `&` or `=` (or inside a token too long for one line), so a signup's slug no longer splits mid-word on a phone (#407). Its text is still exactly the link, so copying it by hand still works.
- On the signup page, a slot with more than one spot counts the spots left, "1 left", where it used to count spots taken, "1/2" (#405). The sign-up sheet already said "1 of 2 spots left", so the list and the sheet counted the same slot in opposite directions, and "1/2" read easily as "1 left". The total is left out of the list, where "1 of 2 left" took about twice the room of "1/2" on a phone; the sheet still shows it, and screen readers hear "1 of 2 spots left". A full or closed slot shows no count, as its "Full" or "Closed" already says it, and "2 left" beside "Closed" offered spots nobody could take. Slots with one spot and unlimited slots show what they did before, and the organizer's builder and Responses tab are unchanged.
- Reminders are set on the date field itself: the field editor on the Build tab has a "Send a reminder email before this date" checkbox, one date field per signup carries it (a bell marks it in the fields list), and the Settings tab's reminders card is gone.
- Reminders go out a fixed 24 hours before a slot. The per-signup lead time (`reminderLeadHours`, 2/24/48/72h) is gone: `slot_at` pins the organizer's wall clock to UTC because a signup carries no timezone, so a short lead was wrong by the organizer's UTC offset, and a longer one was rarely what anyone meant. Migration `0005` drops the stored value; `sendReminders` remains the only off switch.
- `settings.reminderFromFieldRef` is now always the date field slots take their instant from — calendar links, date ordering and reminder timing all read it. It is set on creation (the first date field), moved by the field services when that field is deleted or retyped, and refused by `PATCH /api/signups/[id]` when it names anything else; an omitted key keeps the current anchor instead of clearing it. Migration `0005` pins it on existing signups and rebuilds `slot_at` where the old auto-pick had resolved to nothing.
- The reminder time-of-day field is paired with the chosen date field rather than picked globally, so a return date can no longer be stamped with a departure time.
- The public signup page's header is the instance name alone, linked to the homepage. The landing page's example card, which mocks that page, drops the same segment and now reads its brand from `NEXT_PUBLIC_INSTANCE_NAME` instead of hardcoding "OpenSignup" (a self-hosted instance was showing someone else's brand in its own example). The `· Public signup` segment beside it named nothing a participant could act on — they arrive from a shared link, and the title and Sign-up buttons already say what the page is — and "Public" was ambiguous: true in the sense the product means it (no account, anyone with the link), but just as readable as "publicly listed", which these pages are not.
- Removed the orphaned `/app/signups/[id]/fields` and `/app/signups/[id]/slots` pages and the server actions only they used. Neither was reachable from the signup tabs; the Build tab already covers field and slot editing and grouping.
- Removed the unused idempotency-key store: `src/lib/idempotency.ts` was never called, so the `idempotency_keys` table was never written. Migration `0009` drops the empty table. The rate-limit table it shared a schema file with now lives in `src/db/schema/rate-limits.ts`.
- Removed four activity event types that nothing writes: `commitment.orphaned`, `signup.duplicated`, `reminder.scheduled` and `reminder.failed` (#244). `docs/telemetry.md` listed them as fired, and its reminder health query counted two of them, so those columns always came back 0; it now counts sends, and a separate query counts commitments with failed sends in pg-boss's own tables. The catalogue also gains the events it was missing (`slot.reordered`, `commitment.confirmation_sent`, `reminder.opted_out`, `reminder.opted_in`), its payloads and actors now match what the code writes, and it documents the organizer-actor `signup.viewed` the Build tab writes, which the example view counts now leave out. Comments that still described an `orphaned` commitment status, removed earlier, are corrected. `event_type` is plain text, so no migration is needed.
- A participant's `email` and `email_lower` may now both be null, for signups that make the email optional (#378). Migration `0011` drops the two `NOT NULL`s and adds a check that the columns are null together, and not blank when set; the unique index on `(signup_id, email_lower)` is unchanged, and lets any number of participants without an email share a signup. - A participant can no longer take more spots through their edit link once sign-ups have closed. Signing up, and moving to another slot, is refused when the signup is closed or archived, its closing time (`closesAt`) has passed, the slot is closed, or the slot is inside the signup's lockout window (`lockoutHoursBeforeSlot`), but raising the number of spots on a place already held checked none of these. So anyone already signed up could add spots after the organizer closed the signup or the slot. `PATCH /api/commitments/[id]` now refuses an increase with `closed` by the same rules, which signing up and the edit page now share, and logs it as a failed attempt like a refused sign-up. The edit page shows a "Sign-ups have closed" notice and no longer offers more spots than the participant holds, and a save refused because sign-ups closed after the page loaded says "Sign-ups have closed, so you can't add more spots." rather than the API's message. Lowering the number, changing a name or notes, and cancelling still work, since they only give places back or correct details.
- Deleting a signup now also stops its slots, fields, activity log and CSV export being served. The four organizer routes reading those never checked `deleted_at`, so a deleted signup kept answering on its id to members of its workspace — the export with every participant's name and email address — long after it had vanished from the organizer's list and the public page. The slots, activity and export routes now go through one `getSignupRowForOrganizer` in the signups service, and `listFields` behind the fields route checks `deleted_at` too. The activity route's `?limit=` is also rounded down to a whole number; a fraction such as `1.5` used to fail with a 500.
- A deleted signup no longer takes sign-ups or edits. Deleting keeps the signup's status as it was, and signing up checked only that status, so an open signup kept accepting people after it was deleted: anyone with the page still open, or a slot id, could sign up, and got a confirmation email for a signup the organizer thought was gone. Adding, editing or deleting a field, reordering slots and deleting a slot went through as well, each writing to the activity log of a signup that every read calls not found, and a participant's edit link still let them change their place or take more. The organizer's services and signing up now load a signup through `readLiveSignup` or the signup lock (`lockSignupForWrite`) in `src/services/locks.ts`, which both skip a deleted signup, the lock including one deleted while it waited. A participant's edit link is not found, like the signup's own page, including an edit or cancel that was waiting on a lock when the delete landed, and the confirmation email is not sent if the signup has been deleted by the time it goes out. Publishing, closing or archiving a signup that is deleted at the same moment is not found rather than a status change on the deleted row. On the sign-up sheet and the edit page, a slot or signup removed after the page loaded now reads "Sorry, this is no longer available" rather than the API's "not found". The privacy page said deleting a signup removes its commitments; it takes them off the site, but the rows stay in the database until someone asks for them to be erased, and it now says so.
- A post-login `callbackUrl` on `/login` or `/login/check` can no longer send the browser to another site. `safeCallbackUrl` checked the value as a string, but a browser drops tab, LF and CR characters before reading a URL, so a value that passed the check could still arrive as a link to another host. It now parses the value, keeps it only if it stays on this site, and checks that the path it hands back cannot be read as another host either. The path it returns is the parsed one, so `.` and `..` segments are resolved and characters such as spaces come back percent-encoded. A `callbackUrl` given twice in the same address used to make both pages fail with a server error; it now falls back to the dashboard like any other value that can't be used.
- SMTP on port 465 works without setting `SMTP_SECURE`. An unset or blank value was read as `false`, so the app spoke plain text to a port that expects TLS from the first byte, and every email failed, sign-in links included. Blank now picks from the port: TLS on 465, otherwise STARTTLS if the server offers it. `.env.example` used to ship `SMTP_SECURE=false`; if you copied that and use port 465, clear it. A mail host that is down now fails a send in about 10 seconds for each address its name resolves to (nodemailer tries them in turn) instead of 2 minutes for each, and the sign-in request gives up on a send after 30 seconds rather than waiting on the mail server for up to 10 minutes.
- The commit sheet on `/s/[slug]` locks page scroll while it is open. It was a hand-rolled `fixed inset-0` overlay, so on a phone the list kept scrolling underneath it: the row you tapped slid away mid-form and the sheet read as a floating toast rather than a modal. It is now the shared `BottomSheet` the organizer UI already uses, which brings Escape-to-close, a focus trap, a real `role="dialog"`, hiding the rest of the page from assistive tech, a scrollable body under the 85vh cap (the form stays reachable with the keyboard up) and safe-area padding. The sheet's title carries the slot name, so the form body no longer repeats it as a heading; autofocus is now scoped to this dialog's own fields, where a document-wide query could focus another row's email input. Two consequences of moving to the shared component are worth knowing: the sheet/card breakpoint is `md` (768px) rather than the old dialog's `sm` (640px), so 640–767px viewports now get the full-width sheet instead of a centred card; and a commit in flight holds the sheet open against Escape, the backdrop and the close X alike, which is greyed out to match.
- The commit sheet is announced by the same disambiguated name as the button that opened it (`Sign up for Sat, May 16, Cookies, Vinland Elementary`), not the bare slot title. On a date-grouped signup every date has its own "Cookies", so the short name told a screen-reader user neither which slot they had landed on nor that the sheet was a sign-up form. On screen the heading stays the slot's own name and now wraps to two lines instead of truncating to one — it is the only place the sheet states the slot, and one clipped line lost the end of it at 390px.
- A commit error (a slot that filled up while you were typing, a rejected email) scrolls itself into view inside the sheet. It renders below the fields, so on a short viewport with the keyboard up the only visible sign of a failed submit was the buttons becoming live again.
- Slot rows on the public page no longer truncate their own details on a phone. A fixed right rail (a 36px count column and a 96px button column) left ~160px for text at 390px, so the single clamped meta line dropped its last segment — usually the location — from every row. The rail is now 80px below `sm` (96px above) and the meta line wraps instead of clamping. The text column measures 224px at 390px on an uncounted row and 176px on one that also shows a count; nothing clips at 360px or 390px. At 320px a counted row is still tight enough to clip its last meta segment.
- The `0/1` counter is gone from capacity-1 slots, which is most of them. It made a reader decode a fraction to learn "nobody yet", which the Sign-up button already said, and it was unlabelled for screen readers ("zero slash one"). Real fractions (`2/4`, `10/12`) still show and now carry an sr-only sentence; a fixed-width column used to clip `10/12`. An uncapped slot no longer renders a bare, denominator-less `0`.
- Every state of a slot row's action occupies the same box. "Full" and "Closed" were narrow labels hugging the row's edge next to an 82px "Sign up" pill, so one control's states did not line up with each other down the column. They now share one box: 80px below `sm`, 96px above. Note this is a deliberate divergence from design-system/ui_kits/participant/SlotRow.jsx, which centres a content-width child in a 96px wrapper rather than making every state the same width — the kit correctly identifies the drift (`justify-end` where it should centre) but does not ask for this fix.
- The inert "Full"/"Closed" label is `text-sm`, matching the Sign-up button and Edit link it stands in for, and the size now lives in the shared `ACTION_SIZING` rather than at six call sites. This one goes against the design system, which documents `--text-xs` as "pill labels" and steps the inert label down a size from the action: the judgement here is that `text-ink-soft` already carries the de-emphasis and a second signal only made the column ragged.
- Each slot row's action is named after its own slot (`Sign up for Wed, Sep 30, vs Gerald`), not a bare `Sign up` repeated once per row, so a screen-reader user can tell which slot they are committing to. The name is built from the group label, the title and the meta segments together: on a signup grouped by date the title of every row is only its _time_, so title alone would have moved the collision rather than removed it.
- Row actions meet a 44px minimum touch target below `sm` (iOS HIG 44pt, Material 48dp). They measured 32px, in a list whose whole purpose is tapping one row out of many on a phone. From `sm` up they sit at 36px, the height the real Sign-up button already was, so the production button is unchanged on a pointer and the Edit link and Full/Closed label join it instead of sitting at 34px and 28px.
- Self-hosting with `docker-compose.prod.yml` works with the `.env` that `.env.example` produces (#236). Compose now builds `DATABASE_URL` from `POSTGRES_USER`/`POSTGRES_DB`, points it at the `db` service, and passes the password as `PGPASSWORD`, so it needs no URL-encoding; before, the copied `localhost` URL made the migrate step fail with `ECONNREFUSED`. Operators who run their own Postgres set `EXTERNAL_DATABASE_URL` instead: **if you already point this compose file at an external database through `DATABASE_URL` in `.env`, move that value to `EXTERNAL_DATABASE_URL` before upgrading**, or the app will use the empty bundled database.
- The Compose web container now passes its healthcheck. It pins `HOSTNAME=0.0.0.0` (Docker's default, the container id, left `127.0.0.1` unbound) and `PORT=3000` (a `PORT` in `.env`, meant for the host port, moved the server off 3000).

Before, the build ignored it, so canonical links, `sitemap.xml`, `robots.txt` and Open Graph URLs always said `http://localhost:3000`. `.env.example` still ships that localhost value for local development, so self-hosters must set their own address; the build does not catch a value left unchanged.
- The README Quickstart works on a fresh clone. `.env.example` leaves the required branding values blank, so the first page load under `pnpm dev` threw `Invalid site config`; CI never saw it because it sets them. `pnpm dev` now fills blanks with obvious placeholders ("OpenSignup (dev)", `dev@example.com`, "your jurisdiction (dev placeholder)"). `pnpm build` and Docker builds still fail when they are missing.

- Adding, editing or deleting a slot field now rebuilds `slots.slot_at`. Previously only deleting the chosen date field did, so a field change could leave some slots stale and others null depending on edit order.

The build page never sends one, so every field it added sorted ahead of the template's date column (`DEFAULT_TEMPLATE` pins it at 1) and reappeared mid-grid after a reload. Appends take a row lock on the signup so two concurrent adds cannot claim the same position.

- A date-only slot is anchored at noon UTC rather than midnight, so its day-before reminder lands on the day before in every timezone from UTC-11 to UTC+11 (it used to arrive two days early for organizers west of Greenwich). Its calendar export is now an all-day event rather than a timed one at 12:00Z. Migration `0006` moves existing date-only slots.
- "Add to calendar" puts a timed slot at the hour the signup page shows (#304). The file wrote the slot's wall-clock time as UTC (`DTSTART:…Z`), so every calendar outside UTC moved it: a 3:15 PM slot in November showed at 7:15 AM in Los Angeles and 2:15 AM the next day in Sydney.
